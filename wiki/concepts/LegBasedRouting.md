## Definition

Leg Based Routing is the dynamic long-haul routing approach where the network is modeled as a directed graph of depots ([[MdmLocations]]) connected by long-haul tour legs, and a route between two locations is computed via shortest-path on this graph using [[Neo4jRouting]]. It is intended to eventually replace the rule-based long haul routing approach. Each tour leg can be implemented by one or more line haul elements (operational view with vehicle type, cost, departure/arrival schedule).

## Key Information

**Network model:**
- Depots = MDM locations (consumed via Kafka, cached locally for performance).
- Tour Leg = directed connection between two depots with attributes (distance, internationalFlag, validity window).
- Line Haul = implementation of a tour leg with vehicle type, cost, schedule.

**Initial network bootstrap (per [[network-leg-based-routing]]):**
- International network: from UniQue TBLHTOURLEG (~up-to-date per business).
- DE national network: from the routing matrix Excel.
- Other-country national networks: artificially generated by connecting each main location to its country's international HUB.

**Goals (per [[migration-concept-routing]]):**
- Easier administration - no need to manually define next-location per source.
- Built-in route plausibility checks against LH traffic.

**Use in Shipper Specific Routing (per [[shipper-specific-routing-route-finder]]):**
- For shipper-specific bundle routing, build a per-(shipper, finalLocation) subgraph that excludes forbidden legs, then run shortest-path on the subgraph.
- Maintenance burden: excluded-leg lists must be updated whenever new connections are added.

**Open items (per migration concept):**
- Restrict legs used based on parcel attributes (e.g., tires).
- Performance of shortest-path algorithm at scale.
- Data quality of LH tour legs in UniQue.
- Responsibility model for LH tour leg administration.
- Export to UniQue for legacy consumers.
