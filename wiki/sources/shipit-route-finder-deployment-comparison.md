## Summary

This DRAFT design document (ISRS-21427, under Epic ISRS-19336) compares two deployment models for the Route Finder component when integrated with ShipIt on-premise for Windows. The two options are: WAR deployment inside WildFly (ShipIt's existing servlet container) vs standalone JAR deployment as a separate Windows service. The recommendation is **standalone JAR deployment** for stronger isolation and independent upgradeability, though at the cost of a new Windows service and additional HTTPS port.

## Key Claims

- ShipIt backend and frontend are downloadable from shipit-download.gls-group.eu; ShipIt runs as a Windows service after installation.
- Route Finder's REST API URL: `https://127.0.0.1:8443/rtg/routefinder/v1/` (WAR) or `https://127.0.0.1:8444/routefinder/v1/` (JAR).
- Config stored in `gls\shipit_backend\config\configuration.properties`; DB passwords are encrypted.
- Route Finder must support the same DB password encryption algorithm as ShipIt in order to decrypt shared DB credentials.
- AWS Parameter Store is not available in on-premise deployments; changeable/sensitive settings (DB credentials, partner client credentials) must be stored in DB instead.
- Encryption of client credentials: the partner client secret (and potentially client ID) must be encrypted before being stored in DB. Open issue: how to manage the encryption key within Route Finder.
- DB credentials are generated by the ShipIt installer and encrypted; Route Finder decrypts at runtime. Open issue: how to securely share the encryption key between the installer and Route Finder across Windows and Linux.
- WAR deployment: no additional process, smaller memory footprint (~50–150 MB saved), but constrained by ShipIt's WildFly version (ShipIt currently uses WildFly 26; Route Finder requires WildFly 38).
- JAR deployment: fully independent process with its own JVM, independent upgrades, easier isolation and troubleshooting; requires new port and Windows service.
- **Recommendation: JAR standalone deployment.** ShipIt may migrate away from WildFly in a future version.
- WildFly upgrade to v38 is planned for ShipIt 6.x (before October 2026), or possibly earlier in 5.x.

## Evidence and Notes

- WildFly version conflict is the decisive technical blocker for WAR deployment: Route Finder requires WildFly 38, ShipIt backend supports only WildFly 26.
- Example environment variables passed as `-DPARTNER_BE_CLIENT_ID`, `-DPARTNER_BE_CLIENT_SECRET`, `-DDB_PASSWORD`, etc., in `standalone.conf.bat` (WAR) or `startRouteFinder.bat` (JAR).
- JAR deployment: new keystore required for Route Finder HTTPS; ShipIt backend must configure corresponding trust store.
- Recommended install path: `gls\shipit_backend\rtg\`
- Logging: Route Finder should write to `C:\gls\shipit_backend\log\rtg\route-finder.log`.
- CPU usage expected to be similar between both deployment models (driven by request count, not deployment model).
